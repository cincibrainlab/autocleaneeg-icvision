# Mouse Mode Plan

## How The Prompts Work Today

There are currently two prompt paths:

1. `single` layout
   - Code path: `label_components()` -> `classify_components_batch()` -> `classify_component_image_openai()`
   - Prompt source:
     - default: `prompts/default.txt`, loaded by `load_prompt("default")` in [`src/icvision/config.py`](/Users/sueo8x/Documents/Github/autocleaneeg-icvision/src/icvision/config.py)
     - override: CLI `--prompt-file` or Python `custom_prompt=...`
   - Behavior:
     - one ICA component image per API call
     - prompt is sent as raw text
     - model must return one JSON object: `{"label": ..., "confidence": ..., "reason": ...}`

2. `strip` layout
   - Code path: `label_components()` -> `classify_components_batch(layout="strip")` -> `classify_components_strip_batch()` -> `classify_strip_image()`
   - Prompt source:
     - hardcoded `STRIP_PROMPT_TEMPLATE` in [`src/icvision/config.py`](/Users/sueo8x/Documents/Github/autocleaneeg-icvision/src/icvision/config.py)
     - generated by `get_strip_prompt(n_components)`
   - Behavior:
     - multiple ICA components in one image
     - model must return a JSON array, one object per labeled component (`A`, `B`, `C`, ...)

### Important current constraint

The prompt system is not actually mode-aware yet. The default prompt text is effectively written for human EEG, especially:

- periocular / frontal eye rules using human electrode assumptions (`Fp1`, `Fp2`, `F7`, `F8`)
- “EGI128 nets” language in docs
- human-style spatial heuristics in both the single prompt and strip prompt

So adding `Mouse` mode should not just mean “swap one prompt file”. It should mean making prompt selection explicit across both layouts.

## What Should Change For Mouse Mode

### Goal

Add a project-level classification mode switch:

- `human` = current behavior
- `mouse` = same pipeline, same output schema, different prompt heuristics for ICA morphology

### Design principle

Keep everything downstream unchanged if possible:

- same labels
- same JSON contract
- same report generation
- same exclusion logic

Only the classification instructions should change first. That is the lowest-risk version.

### 4. Rewrite heuristics, not output schema

Mouse mode should change the reasoning rules:

- remove dependence on human periocular geography terms where they are too specific
- describe eye components as anterior/rostral, often broad or asymmetric, rather than relying on human frontal electrode names
- emphasize that mouse ICA topographies may be compressed, shifted, or less obviously “human dipolar”
- make spectral and temporal cues carry more weight when topography is ambiguous

### 5. Add tests at the prompt-selection layer

Add unit tests that verify:

- `human` single mode loads human single prompt
- `mouse` single mode loads mouse single prompt
- `human` strip mode uses human strip template
- `mouse` strip mode uses mouse strip template
- invalid mode raises a clear `ValueError`

Files likely affected:

- [`tests/test_core.py`](/Users/sueo8x/Documents/Github/autocleaneeg-icvision/tests/test_core.py)
- new config-focused tests, likely `tests/test_config.py`
- existing strip tests if prompt generation signature changes

### 6. Document the limitation clearly

Update docs to say:

- `human` is current default
- `mouse` is prompt-tuned, not yet a separately validated classifier
- users should validate on a mouse-labeled benchmark set before trusting auto-exclusion

## How These Assets Should Change The Plan

The project should not ship `Mouse` mode based only on prompt intuition. It should be verified against the added review corpus.

### Add a validation-first workflow

Before finalizing prompt wording:

1. Use the decision CSVs to identify examples explicitly marked as heart-rate ICs and examples without HR notes.
2. Open the matching ICA PDFs from the zip archives and confirm what the PSD actually looks like in those positive and negative cases.
3. Verify that the proposed prompt language matches the reviewed examples:
   - HR positive cases should show regularly spaced PSD peaks
   - non-HR cases should not be classified as heart when those peaks are absent
   - split-HR cases should be represented in the prompt and in the acceptance tests
4. Use the example images as quick visual references when rewriting prompt language and documentation.

### Add dataset-backed acceptance criteria

Mouse mode should only be considered ready when the following checks are run against the newly added assets:

- Known HR-positive examples from reviewer notes are classified as `heart` consistently.
- Examples without regularly spaced PSD peaks are not classified as `heart`.
- At least a sample from each archive (`rest`, `rest2`, `chirp`) is reviewed so prompt behavior is not tuned to a single recording context.
- Split-HR examples are included in the review set and correctly handled by the prompt.

### Add explicit artifact-to-source mapping

The plan should state that each prompt revision must be justified with source examples from the new assets. In practice:

- every wording change for `heart` should be traceable to reviewed ICA PDFs and/or notes in the decision CSVs
- if a heuristic is not supported by the review corpus, it should be marked as provisional rather than treated as a settled rule

### Phase 2

Evaluate on a mouse benchmark set.

- compare human prompt vs mouse prompt
- inspect confusion between `brain`, `muscle`, `channel_noise`, `other_artifact`, and `heart`
- tune prompt wording based on actual failure cases

### Phase 3

Optional species-specific policy.

Possible future changes if needed:

- different default confidence threshold for mouse
- different default `labels_to_exclude`
- optional mouse-specific labels if evidence shows the shared label set is insufficient

## Risks

1. The current strip prompt and single prompt are not equivalent even for human mode, so adding mouse mode without harmonizing them may produce inconsistent mouse behavior between layouts.
2. If mouse topography differs enough, prompt changes alone may not be enough; classification errors may concentrate in `eye` vs `brain` and `muscle` vs `channel_noise`.
3. If the plots themselves are optimized for human interpretation, prompt changes may underperform until visualization choices are also revisited.
4. If the reviewed CSV notes and PDF examples are not used systematically, the prompt may overfit to assumptions rather than the available mouse evidence.

## Recommendation On Prompt Style

Use the same response contract as today:

- single mode: one JSON object
- strip mode: JSON array

But make the mouse instructions more conservative:

- prefer `other_artifact` when the morphology does not cleanly match
- do not over-call `eye` from topography alone
- do not rely on exact human electrode-name geography

## Example Mouse Prompt: Single Component

Suggested file: `prompts/mouse_single.txt`

```text
Classify this MOUSE EEG ICA component into ONE category and provide your answer in JSON format.

Important context:
- This is mouse EEG, so ICA topographies may look different from human scalp EEG.
- Do NOT rely on human-specific electrode heuristics such as requiring classic Fp1/Fp2/F7/F8 periocular patterns.
- Give more weight to the combination of time series, spectrum, and whether the spatial map looks biologically plausible, rather than expecting human-like scalp geometry.
- If the pattern is ambiguous, prefer "other_artifact" over forcing a confident label.
- Mouse heart rate is usually about 7.5-12.5 Hz (beats per second).
- For HEART detection, use the PSD as the primary evidence source.
- In the PSD, look for regularly spaced peaks separated by about 7.5-12.5 Hz across the visible frequency range, especially within 1-55 Hz and 65-100 Hz. The 55-65 Hz region is often notched and should not be used.
- Sometimes the heart pattern is split across 2 ICs: one IC may show regularly spaced heart-rate peaks mainly between 1-50 Hz, while another IC may show regularly spaced heart-rate peaks mainly between 65-100 Hz.
- If an IC's PSD shows no signs of regularly spaced heart-rate peaks, it is NEVER a "heart" component.
- Do NOT use the short top-right scrolling time-series window for heart detection because it only shows the first 2.5 seconds and can be misleading if the beginning of the file contains artifact.

Categories:
- "brain": Spatially plausible neural topography with a smooth dipolar or distributed field pattern, and a generally 1/f-like spectrum that decreases with frequency. May show rhythmic structure rather than abrupt artifact transients.
- "eye": Ocular-like component, usually strongest in anterior/rostral channels, often dominated by very low frequencies, with slow deflections, step-like shifts, or blink-like transients in the time series. Topography may be broad, asymmetric, or less classically dipolar than human eye ICs.
- "muscle": Myogenic artifact, often with relatively elevated high-frequency power, flatter or rising high-frequency spectrum, spiky/irregular time series, and focal or edge/skull-adjacent topography. If high-frequency activity is the clearest feature, favor "muscle".
- "heart": PSD shows regularly spaced peaks consistent with mouse heart rate, typically separated by about 7.5-12.5 Hz. This may appear in 1-55 Hz, 65-100 Hz, or be split across two different ICs. Do not require human-like ~1 Hz cardiac timing.
- "line_noise": Narrow sharp spectral peak at mains frequency or harmonics, not just a notch or dip from filtering.
- "channel_noise": Extremely focal, implausible single-channel hot spot or isolated sensor-dominated pattern, usually without a clean dipole and with noisy, erratic, or unstable signal characteristics.
- "other_artifact": Artifact or mixed component that does not cleanly fit the categories above, or any ambiguous component where classification is uncertain.

Decision rules:
- For mouse data, do not require human-style frontal eye dipoles to call "eye".
- Favor "brain" only when the spectrum is generally 1/f-like and the topography looks spatially coherent rather than isolated or noisy.
- Favor "muscle" when high-frequency contamination is the dominant feature, even if the map is focal.
- Favor "heart" only when the PSD shows regularly spaced heart-rate peaks; if those peaks are absent, do not classify as "heart".
- Favor "channel_noise" only for extremely localized single-sensor patterns that look technically implausible as biological sources.
- If unsure between two artifact labels, use the one best supported by spectrum and time series; if still unsure, use "other_artifact".

Respond with JSON:
{"label": "category_name", "confidence": 0.0-1.0, "reason": "brief explanation"}
```

## Example Mouse Prompt: Strip Layout

Suggested file: `prompts/mouse_strip.txt`

```text
Classify each of the {n} MOUSE EEG ICA components shown in this grid (labeled {labels}).

Each component shows:
- Topography map
- Time series
- Continuous-data / ERP-style image
- Power spectrum

Important context:
- These are mouse ICA components, not human EEG components.
- Mouse IC topographies may be compressed, asymmetric, or less classically human-looking.
- Do NOT depend on human periocular electrode-name rules.
- Use spectrum and time-series evidence heavily when topography is ambiguous.
- If a component is ambiguous, prefer "other_artifact" over a forced label.
- Mouse heart rate is usually about 7.5-12.5 Hz.
- For HEART detection, use the PSD as the primary evidence source.
- Look for regularly spaced PSD peaks separated by about 7.5-12.5 Hz across 1-55 Hz and 65-100 Hz. The 55-65 Hz range is commonly notched and is not reliable for this check.
- Sometimes mouse heart activity is split across 2 ICs: one component may carry the regularly spaced peaks in 1-50 Hz, while another carries them in 65-100 Hz.
- If a component's PSD does not show regularly spaced heart-rate peaks, it is NEVER "heart".
- Do NOT use the short top-right scrolling time-series window for heart detection.

Categories:
- "brain": Spatially coherent neural-looking field pattern with a generally 1/f-like spectrum and non-artifactual temporal behavior
- "eye": Anterior/rostral ocular-like component with very low-frequency dominance and slow or blink-like deflections; may be broad or asymmetric
- "muscle": High-frequency or flatter/rising high-frequency spectrum with spiky/irregular temporal activity, often focal or edge/skull-adjacent
- "heart": PSD shows regularly spaced peaks consistent with mouse heart rate, typically separated by about 7.5-12.5 Hz; this may appear in 1-55 Hz, 65-100 Hz, or across two separate ICs
- "line_noise": Sharp narrow spectral peak at mains frequency or harmonics
- "channel_noise": Extremely focal single-channel pattern with implausible topography and noisy/unstable signal
- "other_artifact": Mixed, unclear, or uncategorizable artifact

Decision priorities:
- If the PSD shows regularly spaced heart-rate peaks, classify as "heart".
- If high-frequency contamination is the dominant feature, classify as "muscle".
- Use "channel_noise" only for very localized single-sensor patterns.
- Use "eye" for anterior low-frequency ocular-like components even if they do not match a human frontal dipole.
- Use "brain" only when the component looks spatially coherent and spectrally 1/f-like.
- If uncertain, use "other_artifact".

Respond with JSON array (one object per component):
{json_example}
```
